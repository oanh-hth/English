# 4.3 · AppProvider and useApp with Context

**Phase 4:** [State management and hooks](README.md) · **Edit:** `app/client/src/state/AppContext.tsx` · **Tests:** `tests/phase-4/4.3-app-context.test.tsx`

## What you build
A Context provider that holds the app state, saves it, and tells the app when it changes.

The comments in `app/client/src/state/AppContext.tsx` describe the exact behaviour. The tests in `tests/phase-4/4.3-app-context.test.tsx` are the full specification: read them, they're short.

## Steps
1. `useReducer(appReducer, storageKey, load)`: the third argument is a lazy init function that gets `storageKey`.
2. Keep the last state you handled in a ref (`useRef(state)`) and return early from the effect when `state === ref.current`. A "first render" flag is not enough: in development, `<StrictMode>` runs every effect twice on purpose to find bugs like this.
3. Keep `onChange` in a ref so a new function from the parent doesn't re-run the effect.
4. `useApp`: `useContext`, and throw the given message when it is `null`.
