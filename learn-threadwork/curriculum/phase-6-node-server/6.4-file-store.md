# 6.4 · Atomic file storage and the state API

**Phase 6:** [Node.js server with Express](README.md) · **Edit:** `app/server/src/storage/fileStore.ts` · **Tests:** `tests/phase-6/6.4-file-store.test.ts`

## What you build
Saving the app state to files, safely, with conflict detection.

The comments in `app/server/src/storage/fileStore.ts` describe the exact behaviour. The tests in `tests/phase-6/6.4-file-store.test.ts` are the full specification: read them, they're short.

## Steps
1. `fileFor(userId)`: remove unsafe characters with a regex, throw on empty, `path.join(dir, name + ".json")`.
2. Read: `JSON.parse(await readFile(...))`; when `err.code === "ENOENT"` return `null`, otherwise rethrow.
3. Write: read the current copy, check the conflict rule, `mkdir(dir, { recursive: true })`, write `.tmp`, then `rename`.
4. The router reads `res.locals.userId`, which `requireAuth` (6.3) sets.

Run the tests while you work:
```
npm run ex 6.4
```
